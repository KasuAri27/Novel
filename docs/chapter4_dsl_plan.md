# 第四章《第一案》· DSL 导入蓝图（coding agent 编码依据）

> 目标：让重写版《魔法少女的魔女审判》能由编码 agent 从正文稿转成 `.story.txt` 并被现有引擎编译、导入（`tests/story_content.test.ts` 零错误）。
>
> 本文是"故事内容 → 引擎 DSL"的映射契约。**coding agent 照本文 §1–§6 编码；content 照正文 chapter1–3（铺垫）与本章设计写。**

***

## §0 铁律摘要（引擎硬约束）

1. `.story.txt` 全部用**同一个** **`@story id=majo_shinpan`** 合并成一部；一章一个文件（或多个上/下文件）。
2. **只有最新一章的末尾可以放** **`@end`** 结局；旧章末尾一律 `[goto] <下一章入口>` 续接（否则 PRIORITY 会遮蔽新结局）。
3. `艾玛` 必须 `immortal`（不可死）；要能死的角色（希罗/梅露露/玛格/诺亚/蕾雅等）**不能** `immortal`。
4. `kill(某角)` 对该角色置死亡；死亡后 `dead(某角)` 为真、`alive(某角)` 为假。
5. 分支判定：同节点内多条 `[choice] ▸ -> 目标 when <条件>`，引擎只显示恰一个命中者（隐身门控路由）。
6. 结局：到达叶子节点（无 choice、无 goto）时，取 `when` 命中且 `priority` 最大者。
7. 叶子节点必须在测试白名单；所有非叶子节点必须有出口。所有节点必须可达。
8. 对玩家隐藏判定：`when`/`do`/flag 都是引擎内部，正文绝不出现在玩家看到的行里（用 `[choice] ▸` 全角不可见标签做纯路由，或把判定塞进合法跳转）。

***

## §1 状态契约（flags / facts / 数值）

> 前三章铺垫积蓄的"冲突解决度＋信任尺"，用一组稳定的**交互状态键**承载。第四章据它们路由第一案。

### 1.1 数值探索度（explore，0 起，可选 +1）

| 键              | 含义                          | 判定阈值                   |
| -------------- | --------------------------- | ---------------------- |
| `explore(希罗)`  | 希罗结"动摇"累积（艾玛护她/动摇她"雪"的认知记忆） | `>=2` ⇒ 希罗被接住（不魔女化）    |
| `explore(梅露露)` | 梅露露信任累积                     | `>=2` ⇒ 梅露露可被信任、不会第一案死 |
| `explore(蕾雅)`  | 诺亚↔蕾雅结"解开"累积                | `>=2` ⇒ 这对结松开，不优先成第一案  |

### 1.2 标志 flag（set true，0/missing 视为假）

| flag 键            | 含义                   | 何时 set                  |
| ----------------- | -------------------- | ----------------------- |
| `第一案_诺亚蕾雅`        | 第一案＝诺亚×蕾雅线           | 第四章路由命中时由 `[enter] set` |
| `第一案_希罗`          | 第一案＝希罗魔女化→守卫反杀       | 第四章命中时 set              |
| `第一案_梅露露`         | 第一案＝梅露露死亡线           | 第四章命中时 set              |
| `无第一案`            | 三对全解决 → 全员线          | 第四章命中时 set              |
| `希罗_动摇`           | 希罗真的开始怀疑"艾玛害死雪"不成立   | explore(希罗)>=2 时 set    |
| `梅露露_信任`          | 梅露露信任艾玛              | explore(梅露露)>=2 时 set   |
| `路线_案件` / `路线_避免` | 世界线分类（沿用引擎既有概念，便于脚注） | 第四章路由 set               |
| `守卫_处置`           | 极端状态下守卫制裁触发（仅艾玛+凶手）  | 终章适用，第四章不设              |

> 说明：`kill(希罗)` 只能发生在"第一案=希罗线"且**未动摇**（`!flag(希罗_动摇)`）时——此时希罗魔女化加重、挑战守卫，被守卫反杀（守卫＝"别人的手"，凶手免处刑，故该案仅 1 死）。若 `flag(希罗_动摇)`，第一案不会杀希罗。

### 1.3 facts（角色信息差，know/knows）

| fact     | 含义               |
| -------- | ---------------- |
| `雪的名字`   | 希罗告诉/艾玛已知"雪"之名   |
| `玛格怕被惦记` | 艾玛看出玛格"怕接好"      |
| `诺亚接住蕾雅` | 诺亚那侧也伸了手（绳两边都有手） |
| `地下层门开着` | 地下层"钥匙孔"之兆       |

## §2 前三章 → 效果映射（coding agent 转译正文稿使用）

> 正文稿的【选择 Exx】A/B/C，在 `.story.txt` 对应节点里写成 `[choice] 文本 -> 下一节点 do set(...)/explore(...,1)`。**每选一项只在正文分支里执行对应效果，不重复累计同一选择。**

### 2.1 希罗尺（E02 / E03 / E14）

- **E02**（晨茶）：A→`explore(希罗,1)`；B→无（理解而不介入）；C→`explore(希罗,1)`。

- **E03**（那支笔/"雪"字）：A→`know(艾玛,雪的名字)`；B→`know(艾玛,雪的名字), know(希罗,雪的名字)`（曲折；高风险）；C→无（守而不问）。

- **E14**（那扇没关严的门）：A→`explore(希罗,1), know(希罗,雪的名字)`；B→`explore(希罗,1)`；C→`know(艾玛,雪的名字)`（若被拒则希罗尺不加）。

> 冠军点：`explore(希罗)>=2` ⇔ 希罗动摇，第四章不会因"希罗线"处刑希罗。

### 2.2 梅露露尺（E04 / E09 / E15）

- **E04**（被推回的茶）：A→`rel(梅露露,艾玛,1)`；B→`explore(梅露露,1)`；C→`explore(梅露露,1), rel(梅露露,艾玛,1)`。

- **E09**（再递一次）：A→`explore(梅露露,1)`；B→`explore(梅露露,1)`；C→`rel(梅露露,艾玛,1)`。

- **E15**（窗台那杯）：A→`explore(梅露露,1), know(艾玛,玛格怕被惦记)`；B→`rel(梅露露,艾玛,1)`；C→`explore(梅露露,1), know(艾玛,玛格怕被惦记), rel(梅露露,艾玛,1)`。

> 冠军点：`explore(梅露露)>=2` ⇔ 梅露露信任艾玛，第一案不会优先杀梅露露。

### 2.3 诺亚↔蕾雅结（E05 / E10 / E16）

- **E05**（那一卷纸）：A→无；B→`explore(蕾雅,1)`；C→`know(艾玛,诺亚接住蕾雅)`。

- **E10**（那两只手）：A→`explore(蕾雅,1)`；B→`explore(蕾雅,1)`；C→无。

- **E16**（悬在半空的手）：A→`explore(蕾雅,1)`；B→`explore(希罗,1)`（观察希罗也会加入护）；C→`know(艾玛,诺亚接住蕾雅)`。

> 冠军点：`explore(蕾雅)>=2 && know(艾玛,诺亚接住蕾雅)`，则这对结几近解开，第四章优先级让位给希罗/梅露露。

## §3 第四章入口 router（真实 DSL 骨架）

> 这是**多节点分支的第一决口**：据前三章状态分流到 4 条第一案/无案分支。放到第四章文件头部。

```
@story id=majo_shinpan title=魔法少女的魔女审判

@entry ch4_s0_router

@node ch4_s0_router
「第二十九天。」我醒来的时候，窗外的海没有声音。岛没有树，晨光却照例直直地落下来。
我已经在这座岛上，过完了整整四个星期。而今天，注定不会像前二十八个早晨那样平静了。
——因为我知道，有些结，终究是要还的。
[enter] set(入场_第四章)
[choice] ▸ -> ch4_split_3p when explore(蕾雅)<2
[choice] ▸ -> ch4_split_shiro when explore(希罗)<2
[choice] ▸ -> ch4_split_meruru when explore(梅露露)<2
[choice] ▸ -> ch4_no_case when flag(入场_第四章)
```

> **路由优先级**（与用户设定"冲突解决度低者先成第一案"一致）：
>
> 1. `explore(蕾雅)<2` ⇒ 诺亚×蕾雅结最紧 → **第一案=诺亚蕾雅**（优先，呼应"最好第一案就是他俩"）
> 2. `explore(希罗)<2` ⇒ 希罗未动摇 → **第一案=希罗线**（魔女化→守卫生）
> 3. `explore(梅露露)<2` ⇒ 梅露露信任不足 → **第一案=梅露露线**
> 4. 全解 ⇒ **无第一案** → 全员/探索/生活线
>
> ⚠️ 优先级三的“梅露露”需放最后：因为 `explore(希罗)` 与 `explore(梅露露)` 各自 <2 时，先判希罗再判梅露露。若两者皆 <2，以希罗线退让——让守卫反杀戏留最重。
> ⚠️ `ch4_no_case` 兜底必须命中（无条件），确保 4 条分支至少一条可见。

### 三条第一案分支各自 `[enter]` 打标

```
@node ch4_split_3p
[enter] set(第一案_诺亚蕾雅), set(路线_案件)
（诺亚×蕾雅线正文：发现→搜查→审判→处刑→余波）
[goto] ch4_after_case_3p

@node ch4_split_shiro
[enter] set(第一案_希罗), set(路线_案件)
（希罗线正文：希罗魔女化加重→挑战守卫→被守卫反杀；艾玛目睹/抢救）
[goto] ch4_after_case_shiro
```

`@node ch4_split_meruru` 同理（第一案\_梅露露）；
`@node ch4_no_case`：`[enter] set(无第一案), set(路线_避免)` → 全员生活/探索收束（引入"安息仪式"线索）。

## §4 审判流程（第一案通用骨架，各分支复用）

> 主题：**众人第一次面对案件与审判**。D 前端规则：审判官方化＝管家宣布启动；守卫可处刑不处刑的魔女；艾玛证明自己不是凶手。

```
@node ch4_trial_≡<分支>≡
守卫：……本设施，受理本次案件。
管家：（宣布开启审判）
（搜查环节：列出【搜查点】循环，若干候选项，每个都 [goto] 回菜单 ── 记 `search_menu`）
[choice] 前往【搜查点·现场】 -> ch4_search_spot
[choice] 前往【搜查点·证物】 -> ch4_search_evidence
[choice] 结束搜查 -> ch4_accusation
```

- 搜查点用「菜单节点 + 各搜查点 \[goto] 回菜单 + 结束搜查」实现（沿用引擎既有惯例）。

- 证物链各自记录为 fact / flag，供庭审方向差分。

- 审判：指控 → 反驳 → 提示（梅露露或替补提示者）→ 锁定凶手 → `[enter] kill(凶手)`；若凶手已在守卫反杀线，则 `[enter] kill(受害者)` 由守卫执行、凶手免处刑。

- 处刑后差分：分"留下证据/原谅线索"等，接余波。

## §5 结局表（@end，只放全树最新章末）

> 第四章不是终章，正常情况下**不在此放主结局**；第四章末 `[goto] ch5_s0_router` 续第五章。
> 但为在 demo（仅第四章）也能收束，可加一组"临时 END"置于本章文件尾部，priority 保守（如 40），且明确 **真结局接入第五章时删除**。

```
（示例·第四章 demo 收尾）
@end END_ch4_demo_3p priority=40 when flag(第一案_诺亚蕾雅)
title 第一案 · 诺亚与蕾雅
text （余波/暂结文字，标记"未完待续"）
text 岛上的日子，还在继续。第五章……
@end END_ch4_demo_shiro priority=40 when flag(第一案_希罗)
...
```

## §6 测试贴合 & coding 清单

- 保持 `艾玛` immortal；希罗/梅露露/玛格/诺亚/蕾雅不 immortal。

- 叶子白名单：真结局接入第五章时，叶子＝第五章尾（更新 `tests/story_content.test.ts` 的 `expectedLeaves`）。

- demo 阶段：叶子必须是 `ch4_*_demo` 系列 + 兜底 `END_fallback priority=1 when alive(艾玛)`（兜底永不落空）。

- 所有 `goto`/`choice` 目标必须存在（可达性测试会抓）。

- `when flag(入场_第四章)` 恒真（因 `[enter]` 已 set）——这是给 coding agent 的"无条件兜底支"写法示范。
