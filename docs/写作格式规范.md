# 写作格式规范（自动解析模板）

> 这是**给作者的唯一格式依据**。`npm run story:build` 按本文件描述解析 `story/chapters/*.md`。
> 照模板写，编译必过；写法跑偏会被 `npm run story:check` 报错。
> 解析器源码：`scripts/build-story.ts`（本文件与它保持一致；改解析器时同步改本文件）。

---

## 0. 一句话

一章 = 一个文件 `story/chapters/chNN.md`；
`#` 是章题，`## S…`（或 `### S…`）是小节（节点），`### 名字` 是说话人，选择块用固定符号包裹。

---

## 1. 文件与命名

| 规则 | 说明 |
|---|---|
| 位置 | `story/chapters/ch01.md`、`ch02.md`…（两位章号） |
| 章号 | 决定节点 id 前缀：ch01 里的 `## S2` → 节点 id `ch01_S2` |
| 选择编号 | `E01`… 全局唯一、全局递增，**不要重号** |
| 逻辑文件 | `story/chapters/chNN.logic.yaml`（选项效果 / 路由，可缺省） |
| 变量表 | `story/vars.yaml`（只有"走向分支"的数值，见第 6 节） |

---

## 2. 行类型对照表（逐字对得上才能被认）

| 你要写的 | 必须写成 | 解析结果 |
|---|---|---|
| 章标题 | `# 第三章　暴风雨前，没有响的雷` | 章名（每章一个，第一个 `#`） |
| 小节／节点 | `## S1　在恶人堆里醒来` 或 `### S-D1　平凡即是奇迹` | 一个节点 |
| 路线分组 | `## ❖ 平行分支二：〔…〕` | 只分组，**不**生成节点 |
| 说话人 | `### 旁白` / `### 艾玛` | 切换后续段落的说话人（默认「旁白」） |
| 正文段落 | 普通文字；连续多行算**一段** | 播放文本（多行保留换行） |
| 选择 | `**【选择 E18｜标题】**`（加粗可选） | 一个选择 |
| 提示语 | 紧跟选择头的**一行斜体** `*……你决定。*` | 选择提示（可选） |
| 选项 | `*A　选项文字*`（`*`＋字母＋**全角空格**＋文字＋`*`） | 选项（恰好 3 个 A/B/C） |
| 回响头 | `**【分支走向展现（E18）】**` | 开始写各选项的回响 |
| 分支标记 | `**若选择 A（说明）：**` | 某个选项的回响段落 |
| 汇合收束 | `**【汇合收束】**` | 回响结束、回到主线（可选） |
| 开发注记 | `> 任意说明` | **不进播放**，可放路由/加分说明 |
| 分隔线 | `---` 或 `***` | 忽略 |
| 章末 | `**——第三章·完——**` | 忽略（纯装饰） |

---

## 3. 一个完整的选择块（照抄结构）

```
**【选择 E18｜那扇门后的第一步】**
*推开门，还是收手——你决定。*

*A　选项一*
*B　选项二*
*C　选项三*

**【分支走向展现（E18）】**
**若选择 A（说明一）：**
### 旁白
A 的回响正文。
**若选择 B（说明二）：**
### 旁白
B 的回响正文。
**若选择 C（说明三）：**
### 旁白
C 的回响正文。

**【汇合收束】**
汇合后的主线正文（可省略）。
```

---

## 4. 硬性规则（违反 = 报错或解析错乱）

1. 每个选择**恰好 3 个选项**，必须是 `A` / `B` / `C`；多一个少一个都会报错。
2. 选项必须**以 `*` 开头、以 `*` 结尾**，字母后跟**全角空格**（`　`）；用半角空格也能认，但请统一全角。
3. 选择编号 `E##` **全局唯一**。
4. 小节必须写成 `## S…` 或 `### S…`——`S` 后面是编号，别带空格（`S1`、`S0`、`S-D1`、`S-A1` 都行）。
5. **说话人名字别用 `S` 打头**（否则会被当成小节）；角色名用中文即可。
6. 提示语必须是选择头**之后、选项之前**的那一行斜体，别写别处。
7. 分支标记的括号与冒号不能省：`**若选择 A（任意说明）：**`。
8. 章末 `——第N章·完——` 只是装饰。

---

## 5. 反例（会出问题）

- ✗ `*A 选项*`（少了全角空格以外还在别处夹了正则符号）——文本可能不对
- ✗ `*D　选项*` —— 只认 A/B/C
- ✗ 一个选择写了 4 个选项
- ✗ `#### 分支走向展现` 少了编号括号
- ✗ 正文里单独一行写 `***`（会被当分隔线吃掉）
- ✗ 在选择块中间随意插一行斜体（会被当正文，留下星号）

## 6. 逻辑文件 `chNN.logic.yaml`

与 md 同目录，按编号对上；没有可以不放。

```yaml
# 选项效果
choices:
  E18:
    A: { effects: [{ var: hiro.explore, add: 1 }] }
    B: { effects: [] }
    C: { effects: [{ rel: [meruru, ema], add: 1 }, { know: ema, fact: 雪的名字 }] }

# 路由：键 = 节点 id；该节点（及其选择）之后的分流
routes:
  ch04_S0:
    rules:                    # 按顺序判断，先匹配先生效
      - { when: "reia.explore >= 2 && hiro.explore >= 2 && meruru.explore >= 2", goto: ch04_S-D1 }
      - { when: "reia.explore < 2", goto: ch04_S-A1 }
      - { when: "hiro.explore < 2", goto: ch04_S-B1 }
      - { when: "meruru.explore < 2", goto: ch04_S-C1 }
    else: ch04_S-D1           # 兜底（必须命中，保证有出口）

# 结局：键 = 节点 id；该节点走到头即为某个结局
endings:
  ch04_S-D2: END_ch04_no_case
```

**效果三种写法**（数组里可叠加）：

| 写法 | 含义 |
|---|---|
| `{ var: hiro.explore, add: 1 }` | 变量 +1（`set: n` 为直接置值） |
| `{ rel: [meruru, ema], add: 1 }` | 二元关系档位 +1 |
| `{ know: ema, fact: 雪的名字 }` | 注入信息差：ema 从此知道「雪的名字」 |

**条件语法（只支持这些）**：变量名 / 数字 / `>= <= > < == !=` / `&& || !` / 括号。
变量必须在 `story/vars.yaml` 里声明。

---

## 7. 写完怎么验

```bash
npm run story:check     # 只校验，不写文件
npm run story:build     # 校验并生成 public/story/story.json
```

校验会报两类信息：**问题（判失败）** 如选项数不是 3、跳转目标不存在、正文残留 `>`；
**提示（不判失败）** 如某选择缺提示语、某选项没有回响文字。

---

## 8. 旧写法也兼容（能认，但建议逐步统一）

为兼容已有章节，解析器同时接受这些旧写法：

- 回响头不加粗：`### 分支走向展现（E01）`
- 分支标记用四级标题：`#### 若选择 A（…）：`
- 选择头不加粗：`【选择 E01｜…】`

新写的章节请统一用第 2 节的加粗写法。
